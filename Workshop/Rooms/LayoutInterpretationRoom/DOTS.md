# Layout Interpretation Room DOTS
Updated: 2026-09-26

## Room Contract

- Room: `LayoutInterpretationRoom`
- Outcome: Build an encapsulated, generator-independent Layout Interpretation subsystem that accepts valid `MapData` plus required architectural/site-purpose and Scale context, claims useful semantic Zones from existing traversable geometry, records Zone metadata without placing content or changing map geometry, and exposes the completed result through a small public surface.
- Scope / prohibited territory: Define the architecture-purpose and Zone catalogs; analyze existing floor geometry; implement Zone claiming, ordered interpretation passes and coverage; package interpretation metadata; expose and validate the subsystem; and maintain Room/current system documentation. Do not modify generated cell geometry or place doors, portals, stairs, traps, scenery, lighting, loot, actors, occupants, furnishings, decorations, or other content. Do not depend on generator internals. Occupant-family adaptation is a possible later system and is outside this Room. Production writes require a later Box-specific Alignment Check and Rob's confirmation before promotion begins.
- Acceptance: A caller can provide any valid generator-independent `MapData`, supported site-purpose tag, and generation Scale; the subsystem produces coherent Zone IDs, architectural roles, tile membership, geometry and relationship metadata; universal and Scale-tiered purpose-required Zone rules are applied in an explicit order; claimed tiles obey ownership invariants; coverage and unzoned floor are reported honestly; invalid or unsatisfiable inputs fail according to the approved contract; downstream systems can consume the result without knowing interpreter internals. Required automated checks pass, current-state/system documentation matches implementation, and human runtime/design acceptance remains recorded separately.
- Authority evidence: Rob established the initial system vision and four-stage traversal on 2026-09-25, then explicitly pivoted the catalog driver from occupant family to architecture/site purpose, directed preservation of family ideation in a non-authoritative pseudo-system document, and issued `Execute` for the pivot.
- Starting state: The Production Map Generation System is documented as returning detached `MapData` with `width`, `height`, and row-major `cells` using `ABYSS = 0`, `FLOOR = 1`, and `WALL = 2`. The Room scaffold and Rob's [`FirstPassIdeation.md`](../../Trashcans/LayoutInterpretationRoom_Retired_2026-09-26/Documents/FirstPassIdeation.md) exist. No Layout Interpretation implementation or Git checkpoint has been established; Git checkpoint is unknown.
