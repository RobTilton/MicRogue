# Generator Room DOTS
Updated: 2026-09-24

## Room Contract

- Room: `GeneratorRoom`
- Outcome: Deliver a bounded, modular layout-generation system that accepts a semantic layout request and returns a connected, boundary-sealed floor/wall geometry map through a controller-owned public boundary.
- Scope: Generation orchestration, semantic-to-concrete parameter resolution, raw geometry generation, bounded window selection, boundary sealing, floor-region discovery, cheap connection correction, deliberate save-or-sunder judgment for unresolved regions, and final geometry validation.
- Prohibited territory: Rendering or painting; decoration; door objects or door semantics; entrances and exits; semantic markers in the returned map; actors; loot; population; persistence; world state; player knowledge; Global Map, Local Map, town, or POI ownership beyond producing requested floor/wall layout geometry.
- Architectural constraints: Components must be modular, encapsulated, compositional, and reusable. The controller owns orchestration, not component internals. The base geometry generator consumes concrete parameters and does not interpret semantic labels. The final public result contains only bounded floor/wall topology.
- Deferred design: Numeric values, catalog storage, catalog merge rules, semantic-label details, generation taxation/scale values, room counts, window dimensions, RoomJudgement rules and thresholds, and internal randomness mechanics are decided only inside their owning Boxes. Production callers receive no seed or reproducibility contract; test/debug tooling may expose or inject randomness without changing the public contract.
- Acceptance: All mandatory Boxes are complete with synchronized documentation; `GeneratorCaller` is exercised across the catalog permutations defined by the completed resolver; returned maps preserve sealed boundaries, contain no floor on the outer edge, contain connected surviving floor geometry, and expose geometry only; connectivity/pathfinding checks pass; required human visual checks are accepted; the AI-facing generator description reflects the completed architecture.
- Authority evidence: Rob supplied `Documents/outline_for_dots_generation.md`, confirmed the 2026-09-24 Alignment Check, and issued `Execute` for this DOTS/document-disposition task.
- Starting state: Git baseline `9cfce5ff6eebe2f1c7b1cecf6f7a31fd52b6059f` plus current uncommitted GeneratorRoom organization and documentation. The working dungeon-field prototype, renderer, tools, and recorded evidence are described in [`CurrentState.md`](CurrentState.md) and the [Generator System Description](../../AI_Facing_Documentation/SYSTEMS_DESCRIPTIONS_FOR_AI/GENERATOR_SYSTEM.md).
